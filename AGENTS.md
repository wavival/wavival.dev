# AGENTS.md

Guidance for AI coding agents working in this repo. See `CLAUDE.md` for full project context, stack, and conventions.

## Rules

- **Lúmina W delivery flow.** `main` is production, `stg` is staging, and `dev` is the integration base. Create human work branches from `dev` with `feature/*`, `fix/*`, or `chore/*` names, then open every work PR to `dev`. Promotions move only `dev` to `stg` and `stg` to `main`; Valentina merges both promotion PRs manually with a merge commit, not squash or rebase, to preserve branch ancestry. Do not push directly to `dev`, `stg`, or `main`. Do not merge or promote while any required check is pending, failing, cancelled, skipped because of another failure, or unavailable. After a work branch is merged into `dev` and the merge is confirmed, delete the local and remote branch.

- **Commit messages.** Use strict Conventional Commits in English: `type(scope): message`. Allowed scopes in this portfolio repo are `api`, `ui`, `db`, `auth`, `ci`, `deploy`, `docs`, `config`, `tests`, `security`, `deps`, `core`, `seo`, and `a11y`. The local `.husky/commit-msg` hook and the CI `commitlint` job both enforce this.

- **Delivery checks.** Required delivery checks for protected branches are `commitlint`, `quality`, `tests`, `security scan`, and `validate-pr-base`. The `quality` job runs dependency audit, format check, lint, Astro type check, build, and CSP hash verification. The `tests` job runs Playwright. The `security scan` job runs gitleaks with the org-level `GITLEAKS_LICENSE` secret. The `validate-pr-base` workflow blocks skipped promotion paths.
- **Auto-merge into dev.** The `auto-merge-dev` workflow enables merge-commit auto-merge for non-draft `feature/*`, `fix/*`, and `chore/*` PRs using the built-in GitHub token with write permissions. Do not use squash or rebase.

- **No em dashes.** Never use the em-dash character (Unicode U+2014) anywhere in this repo: copy, code, comments, docs, commit messages, or PR descriptions. Use normal punctuation instead:
  - colon (`:`) when the second part explains the first,
  - comma (`,`) for a light aside,
  - parentheses (`( )`) for a parenthetical (especially when the aside already contains commas),
  - hyphen (`-`) for ranges or simple separators.
  - This applies to both generated and edited content. Do not substitute an en-dash (`–`) or any other fancy dash either; plain ASCII punctuation only.

- **No arrows or icons in buttons/links unless asked.** Never add `←`, `→`, `↑`, `↓`, or any decorative icon to a `Button`, `TextLink`, or `IconLink` unless Valentina explicitly requests it. Icons appear only on icon-only buttons and the primary button (`icon=` prop); text buttons and links carry none. The components communicate action through their design; adding unsolicited arrows is a style override she will revert.

- **Design system "Señal v4".** The UI follows the Claude Design project `wavival-dev-v4` (files `wavival-dev-v4.dc.html`, `wavival-dev-v4-design-system.dc.html`, `wavival-dev-v4-design.md`). Principles: rules not boxes (1px lines, no shadows); editorial Raleway 800 scale; one blue signal; icons only on icon buttons and the primary button; one-column narrative at full container width; vertical centering; accordion state shown as text. Components follow atomic design in `src/components/{atoms,molecules,organisms}` (template: `src/layouts/Layout.astro`); the old `ui/` and `sections/` folders are gone. Tokens live in `src/styles/tokens.css` (`--bg --surface --line --line-2 --tint --text --muted --link --link-h --blue --btn --btn-h --nav --ok --warn --on-btn`, plus `--container`, `--gut`, `--sec`, `--nav-h`, radii, and `--fs-*` / `--tracking-*`); the pre-v4 names (`--brand-blue`, `--bg-page`, `--accent-link`, `--btn-bg`, `--shadow-base`, ...) no longer exist. Tailwind maps `bg`, `surface`, `line`, `line-2`, `tint`, `ink`, `muted`, `link`, `link-h`, `blue`, `btn`, `btn-h`, `ok`, `max-w-container`, `rounded-control`, and `gut`/`sec`/`nav` spacing to them. Component classes (`.wrap`, `.btn-primary`, `.eyebrow`, `.index`, `.display-xl`, `.chip`, `.nav-link`, `.disclosure`, ...) live in `@layer components` in `utilities.css`. There is no scroll reveal (`data-aos`) and no accordion script: the design is static and the accordion is native `<details>`. Keep `DESIGN.md` and `COMPONENTS.md` in sync with any change here.

- **Keep docs in sync (ALWAYS, mandatory).** ALWAYS update both `CLAUDE.md` and `AGENTS.md` in the same change whenever ANY important change happens in the repository. Non-negotiable, no exceptions. "Important" includes (but is not limited to): infrastructure, dependencies, tooling, repo structure/file layout, build or deploy config (`vercel.json`, `microfrontends.json`, CI), routing/i18n conventions, SEO / schema / JSON-LD / metadata, analytics, design-system or token decisions, and accessibility behavior. Treat the docs as part of the change, never a follow-up: if a change makes any statement in either file wrong or incomplete, fix it before finishing. Applies to Claude and all subagents, every time.

- **Bilingual routing.** ES is the default at root with Spanish slugs (`/proyectos`, `/servicios`, `/sobre-mi`, `/contacto`, `/herramientas`, `/privacidad`); EN mirrors under `/en/` with English slugs. Never hardcode a route that ignores language: resolve targets with `siteRoutes(lang, base)` from `src/i18n/utils.ts` (or the `isEn ? "/en/..." : "/<es-slug>"` ternary), and update the slug map in `src/i18n/utils.ts` (`EN_PAGE_MAP` + `getAltLangUrl`) whenever you add a page or rename a slug. `EN_PAGE_MAP` is exported and also consumed by the sitemap `serialize` hook in `astro.config.mjs`, which emits reciprocal `xhtml:link` hreflang alternates (`es` / `en` / `x-default`, trailing-slashed) for every bilingual URL. Use the bare language codes `es`/`en` (one Spanish/English version each, targeting all speakers), never region codes (`es-CO`/`en-US`), to match the page-head `alternates` and avoid wrongly narrowing geo-targeting. Legacy English-word ES routes 301-redirect to the Spanish slugs in `vercel.json`; the former OKroot slugs `/proyectos/root` and `/proyectos/root-landing` plus their EN equivalents permanently redirect to `/proyectos/okroot` and `/proyectos/okroot-landing`. `getAltLangUrl` special-cases `/404` and `/en/404`: both redirect to the opposite locale's home rather than a translated error page. Translatable data lives in bilingual fields, not just UI strings: `src/data/stack.ts` carries `descriptionEn` / `whyEn` / `toolsEn` (the latter only on categories with translatable chips, e.g. Design & UX, Product Engineering; falls back to `tools` for proper-noun-only categories), rendered via `isEn ? (s.toolsEn ?? s.tools) : s.tools` in `StackGrid.astro` and `s.toolsEn ?? s.tools` in `/en/uses`. When you add a Spanish chip/label to a data file, add its `*En` counterpart too. The current OKroot case-study slugs are `okroot` and `okroot-landing`. Only the Linux-privilege `Root:` strings in the Forgotten Portal CTF data are unrelated and stay as-is.
- **CV source files.** Edit `docs/wavival-dev-cv-es.html` and `docs/wavival-dev-cv-en.html`, then export both with LibreOffice to the existing `public/cv_valentina_ramirez_<es|en>.pdf` asset paths. Keep both locale versions in sync, preserving the two-page, compact Arial sans-serif layout and the existing content unless a specific update is requested.

- **Brand and commercial docs.** `docs/brand.md` and `docs/commercial.md` are living, undated guides for the wavival personal brand (V1: Instagram and LinkedIn in Spanish; services point primarily to Lúmina W; TerraCore and OKroot are Lúmina W products, with only the Semilla plan available for TerraCore and OKroot in early access; the 42% TerraCore figure is not used in public content; CV third-party names and experiences are not V1 content). State only facts verifiable in this repository or recorded as decisions in those files; leave the rest as `[PENDIENTE]`, which blocks only the specific piece that needs it. Never add secrets, client data, exploitable vulnerabilities, or sensitive infrastructure detail to them. Update them when positioning, offer, pricing, or product status changes.

- **OG image assets.** The README-only banner is `assets/banner.png`. Case-study OG images live in `public/images/` as optimized 1200x630 WebP files, generated with a cover crop and stripped metadata. Do not add duplicate project PNG sources to `assets/`. Keep `src/data/projects.ts` image paths and dimensions aligned with those files.

- **Indexing operations.** `public/robots.txt` allows crawling and points to the generated sitemap. Search Console ownership and indexing status are external state: verify the `wavival.dev` Domain property through DNS, submit `https://www.wavival.dev/sitemap-index.xml`, and inspect the home, section, and case-study URLs after production deploys. `public/llms.txt` and `public/llms-full.txt` support AI discovery but do not replace Search Console or guarantee search rankings.

- **SEO and JSON-LD conventions.** All hreflang `href` values and BreadcrumbList/Service `item`/`url` values must carry trailing slashes to match canonical URLs. `Person.image` is an `ImageObject` node (not a bare URL string). `Organization.logo` is an `ImageObject` node. `Person.description` in the `@graph` is a stable Spanish bio constant, not the page-level meta description. The `WebSite` node omits `inLanguage` (shared `@id` must not mutate per locale). `og:image:type` is derived from the OG image file extension (`.webp` yields `image/webp`). `og:type` is per page via the `ogType` Layout prop: `website` (default), `profile` (home), `article` (case studies, which also emit `article:published_time`/`article:modified_time` from `ogPublishedTime`/`ogModifiedTime`). Case studies use per-project OG cards (`project.image`, 1200x630 webp in `public/images/`: `og-terracore`/`og-okroot`/`og-nullbreach`) and per-project `og:image:alt` / `twitter:image:alt` via the `ogImageAlt` Layout prop (from `project.imageAlt`, EN from `project.en.imageAlt`), falling back to the generic locale alt; regenerate OG cards as 1200x630 webp with `sharp`. Service nodes carry `@id` and `priceRange`. Both `ContactPage` pages (`/contacto` and `/en/contact`) also emit a `BreadcrumbList`. Case-study nodes carry an `@id` (`<pageURL>#project`); `SoftwareApplication` nodes use real `programmingLanguage` values (Python, TypeScript, SQL), move frameworks/tools to `softwareRequirements` (from `project.stack`), and set an accurate `applicationCategory` (`project.appCategory`). Case-study `datePublished`/`dateModified` (JSON-LD and the visible date) come from `project.datePublished`/`dateModified` in `src/data/projects.ts` and fall back to the build date only if unset: every project now sets real dates, so `dateModified` no longer churns on each deploy. Set real dates there, never hardcode. In the JSON-LD these are emitted as full ISO 8601 datetimes (`toIsoDateTime()` normalizes a date-only `YYYY-MM-DD` to `YYYY-MM-DDT00:00:00-05:00`; Google's Profile page rich result rejects date-only `dateModified`); the visible label stays date-only. `Organization` carries a `contactPoint`; its `sameAs` excludes its own `url`. `Person.sameAs` uses canonical www + trailing-slash profile URLs. The sitemap `serialize` hook sets a per-type `priority` (home 1.0, sections 0.8, case studies 0.7, legal 0.3). The hero image preload (`<link rel="preload" as="image">` for `profile.webp`) is gated behind the `preloadHero` Layout prop and set only on pages that render the photo (home, about). Twitter cards set `twitter:site`/`twitter:creator` (`@wavival0`), and `Person.sameAs` includes the X profile (`https://x.com/wavival0`). Keep titles <=60 and meta descriptions <=160 characters. `public/llms.txt` (index) and `public/llms-full.txt` (long-form companion, linked from the `## Optional` section) must stay in sync with site content (project metrics, stacks, services, contact).
- **Current OG image set.** The case-study OG files are `og-terracore.webp`, `og-okroot.webp`, `og-nullbreach.webp`, `og-lumina-w.webp`, and `og-blogw.webp`; the default site card is `og-card.webp`. All are 1200x630 WebP files in `public/images/`.

- **Testing.** Run `npm run build` then `npm test`. Playwright serves `dist/` via its own `astro preview` on port **4329** with `reuseExistingServer: false`, so a dev server on 4321 is never reused (a dev server has no sitemap and uses localhost canonicals, breaking the SEO/i18n specs). Every standalone page needs exactly one `<h1>`: `Hero` owns it on the homepage and `PageIntro` on every other page (section headers default to `h2`). The route-coverage spec asserts this. Some specs are pure unit tests (no browser): `redirects.spec.ts` parses `vercel.json` and `microfrontends.json` to lock redirects, proxies, and path ownership; `i18n-utils.spec.ts` tests `getAltLangUrl` and `siteRoutes` directly. `projects.spec.ts` covers the project filters, `theme.spec.ts` the default-dark theme, and `home.spec.ts` the hero image (height 400). Update these when you change redirects or the slug map.

- **CI gates (`.github/workflows/ci.yml`).** `commitlint` enforces pull request commit messages. `quality` runs dependency audit via `npm audit --audit-level=high --omit=dev`, format check, lint via `npm run lint`, type check via `astro check`, build, and CSP hash verification. `tests` runs Playwright, `lighthouse` asserts perf/a11y/best-practices/SEO via `lighthouserc.json`, `links` checks built internal links, and `security scan` runs gitleaks. Run `npm run build` before `lhci`/`links` locally. CI jobs pin Node via `node-version-file: ".nvmrc"` (→ `22`). ESLint uses a flat config (`eslint.config.mjs`: `eslint-plugin-astro` + `typescript-eslint` + `eslint-config-prettier`) and ignores generated `dist/` and `.vercel/` output; Husky runs `lint-staged` on pre-commit and the repository Commitlint rules on commit-msg, followed by the shared checker at `~/.claude/git-hooks/commit-msg` when installed. Keep the lint and commit-message baselines clean. Favicon/manifest icons in `public/` are generated from `brand/logo-w.webp` with `sharp`; regenerate them if the logo changes. Security contact lives at `public/.well-known/security.txt` (RFC 9116); bump its `Expires` date before it lapses. `CHANGELOG.md` follows Keep a Changelog + SemVer: add entries under `[Unreleased]` as you ship, and cut a version section on release.

- **One accessible interactive blue.** Text, links, icons, and focus use `--link` (`#1565c0` light / `#5b8cff` dark, hover `--link-h`); the primary button fill is `--btn` (`#1565c0`, hover `--btn-h`) with `--on-btn` (white) text, theme-independent. White-on-`#1565c0` is 5.67:1; link text on `--bg` is 5.13:1 (light) / 5.93:1 (dark), all >=4.5:1. `--blue` (`#407bff`) fails AA for small text (~3.4:1) and is reserved for fills, borders, indexes, and large/display text. Do not reintroduce a brighter blue for button fills (the retired dodger-blue failed white text at 3.24:1). Focus is the global `:focus-visible { outline: 2px solid var(--link); outline-offset: 2px }` in `global.css`, not per-component ring classes. Icon-only controls tint SVGs from `public/icons/ui/` through a CSS mask using `--link` (`MaskIcon`, `IconLink`), so they follow the theme; the `*-white` files are `<img>` icons inside the primary `Button`. Calendly's `primary_color` is `1565c0`. Dark is the default theme (`.dark` unless `localStorage.theme === "light"`; no `prefers-color-scheme`); `--text-muted` is `#4b5563` light / `#9ca3af` dark.

- **Accessibility behaviors to preserve.** Mobile menu is `inert` while closed and traps focus while open (`src/scripts/nav.ts`); Escape restores focus to the hamburger. NavBar/Footer mark the active page with `aria-current="page"` via `ariaCurrent()` (hash-only links excluded; `Projects` stays current on case studies). The header is sticky (64px) and below 900px the menu is a full-screen overlay with the same ids (`#mobile-menu`, `#menu-btn`). Footer group titles are real `<h2>`s. The theme toggle sets a state-aware `aria-label` in `theme.ts`; the hamburger's `aria-label` is localized and state-aware too (NavBar passes `data-label-open`/`data-label-close` from the `nav.openMenu`/`nav.closeMenu` translations, `nav.ts` reads them on toggle, never hardcoding Spanish). Icon-only links keep a >=44px hit target. Any control with visible text must keep that text inside its `aria-label` (Label-in-Name). The project filter "no results" block is `role="status"` (WCAG 4.1.3) so an empty filter result is announced; the case-study accordion is native `<details>` (`Disclosure`). The single `<meta name="theme-color">` is driven by JS (`theme.ts` `syncIcons` + the pre-paint inline script, default `#0f1117`), not media queries, because the class-based theme (dark by default) does not follow the OS `prefers-color-scheme`.

- **Analytics and RUM.** Umami (cookieless) and Core Web Vitals RUM (`src/scripts/vitals.ts`, the `web-vitals` package) are both gated on `PUBLIC_UMAMI_SRC` + `PUBLIC_UMAMI_ID`: neither the analytics script nor the vitals bundle is emitted unless both are set. Vitals report LCP/INP/CLS/FCP/TTFB to Umami as `web-vitals` custom events over `connect-src` (both `cloud.umami.is` and `analytics.umami.is` are in the CSP `script-src` + `connect-src`). Do not add a third-party RUM/error service without updating the CSP. The CSP `script-src` is **hash-based (no `'unsafe-inline'`)**: it carries a `sha256-*` for every inline `<script>` Astro emits, recomputed from `dist/` by `scripts/check-csp-hashes.mjs` (`npm run csp:check`, in the CI `quality` job). Adding or editing ANY inline script (theme, `define:vars`, etc.; the reveal and accordion scripts no longer exist) changes its hash and is blocked in production until the new hash lands in `vercel.json`; run `npm run build && npm run csp:check` to print it. JSON-LD (`application/ld+json`) is a data block and not gated; `style-src` keeps `'unsafe-inline'` (inline `style` attributes hashes can't cover). CTA click tracking uses Umami's zero-JS automatic capture: key CTAs carry a `data-umami-event="<name>"` attribute (no `window.umami.track()` calls). `Button`, `TextLink`, and `IconLink` forward a `data-umami-event` prop; project app/site links carry an optional `event` field on `ProjectLink` (`src/data/projects.ts`) surfaced by `projectView()` and forwarded by `ProjectActions.astro` (project cards and both `[slug].astro` pages). Event names: `cta-quiero-producto`, `cv-descarga-es`/`cv-descarga-en`, `contacto-email`/`contacto-whatsapp`/`contacto-calendly`, `ver-app-terracore`/`ver-app-root`/`ver-app-nullbreach`. Add new CTA tracking via this attribute, never inline scripts.

- **GitHub widget (build-time).** `/herramientas` and `/en/uses` render the GitHub profile and non-fork repos via `fetchGithubProfile` in `src/data/github.ts`. It is unauthenticated, runs at build time, and fails soft on network errors or rate limits. `curateRepos()` features the single `nullbreach` repo and hides the profile README, this portfolio, and the one-off `prueba-tecnica-logika` test. Remaining non-fork repos appear as learning resources. Both tiers render through `RepoCard.astro`; keep the ES/EN markup aligned.

- **Vercel microfrontends.** `wavival-dev` is the default application and owns `/` plus every path not assigned in `microfrontends.json`. The separate `nullbreach` project exclusively owns `/nullbreach` and `/nullbreach/:path*`. Keep the routing contract aligned with the NullBreach repository. Add future independent projects under unique, non-overlapping prefixes; adding a child route must not change existing portfolio routes. `vercel.json` defines the security headers, immutable caches, legacy redirects, and `/api/*` compatibility proxy.

- Follow all conventions in `CLAUDE.md` (design tokens, dark-mode via `.dark` class, static-only Astro, accessibility, etc.).
